# 大地图攻城 Demo 文档

## 一、功能概述

本 Demo 是一个基于 Unity 的简化版大地图攻城演示，模拟两个阵营（技术部 vs 策划部）之间的城池攻防战。

### 核心玩法
- **阵营设定**：游戏包含两个阵营，分别为 `Tech`（技术部，蓝色）和 `Design`（策划部，红色）。
- **城池系统**：场景中包含 3 座城池，分别为技术部基地、策划部基地和中立城池"长坂坡"。
- **攻城流程**：玩家点击"进攻"按钮后，技术部军队从基地出发，行军至长坂坡，到达后自动进入攻城战。
- **战斗结算**：攻城战中双方兵力随时间递减，技术部兵力耗尽则攻城失败，策划部兵力耗尽则技术部占领城池并获胜。

### 视觉效果
- 军队行军：士兵以随机速度分批出发，向目标城池移动。
- 攻城动画：到达城池后，士兵在城池前方列阵，城池进入"战乱"状态（橙色）。
- 伤害飘字：攻城期间随机生成伤害数字飘字效果。
- 阵营变色：城池根据所属阵营和战争状态实时改变颜色。
- UI 界面：包含进攻按钮、战斗 HUD（实时兵力显示）、胜利面板（重新开始/退出）。

## 二、Demo 操作

### 运行场景
打开 Unity 项目，运行 `Assets/Scenes/SampleScene.unity` 场景。

### 操作步骤
1. **启动场景**：进入场景后，可以看到三座城池分布在大地图上。
   - 蓝色城池：技术部基地（己方）
   - 红色城池：策划部基地（敌方）
   - 红色城池：长坂坡（初始归属策划部）

2. **发起进攻**：点击长坂坡上方显示的红色 **"进攻"** 按钮。

3. **观看行军**：技术部士兵从基地出发，向长坂坡行军。

4. **攻城战斗**：士兵到达后自动进入攻城阶段，屏幕上方显示双方实时兵力。
   - 技术部兵力：20
   - 策划部兵力：10

5. **战斗结果**：
   - 若策划部兵力先降为 0，弹出 **"胜利"** 面板，长坂坡变为蓝色（技术部占领）。
   - 若技术部兵力先降为 0，攻城失败（当前 Demo 中技术部兵力较多，通常能获胜）。

6. **重新开始**：点击胜利面板上的 **"重新开始"** 按钮，重置整个场景。
7. **退出游戏**：点击 **"退出"** 按钮结束运行。

## 三、代码说明

### 1. GameManager.cs —— 游戏总控器

**职责**：管理游戏全流程，包括城池绑定、军队生成与行军、攻城战斗、UI 构建与事件处理。

| 核心成员 | 说明 |
|---|---|
| `Phase` 枚举 | 游戏阶段：`Idle`（待机）、`Marching`（行军中）、`Siege`（攻城）、`Captured`（已占领） |
| `troopPrefab` | 士兵预制体 |
| `troopCount` | 技术部出兵数量（默认 20） |
| `marchSpeed` | 行军基础速度 |
| `designStartCount` | 策划部初始守军（默认 10） |
| `_troopPool` / `_troops` / `_arrivedTroops` | 对象池、行军中士兵、已到达士兵 |

**关键方法**：

- `OnAttackClicked()`：玩家点击进攻按钮，触发军队出发。
- `SpawnMarch()`：协程，分批生成士兵并控制其行军。
- `BuildArrivalSlots()`：计算士兵到达城池前的随机站位点。
- `BeginSiege()`：首个士兵到达后进入攻城阶段，开启兵力消耗计时。
- `Update()`（Siege 阶段）：按时间间隔减少双方兵力，刷新 HUD，生成伤害飘字。
- `KillOneTroop()`：从已到达或行军中移除一名士兵（对象池回收）。
- `CaptureCity()`：策划部兵力归零，占领城池，显示胜利面板。
- `BuildAttackButton()` / `BuildBattleHud()` / `BuildVictoryUi()`：动态构建世界空间/屏幕空间 UI。

### 2. ArmyUnit.cs —— 士兵单位

**职责**：控制单个士兵的行军行为与渲染颜色。

| 成员 | 说明 |
|---|---|
| `HasArrived` | 是否已到达目的地 |
| `IsMarching` | 是否正在行军 |
| `ApplySharedColor(Color)` | 使用 MaterialPropertyBlock 批量修改士兵颜色（避免材质实例化） |
| `BeginMarch(...)` | 开始行军，设置目标点、速度、到达回调 |
| `Release()` | 重置状态并回收到对象池 |

---

### 3. City.cs —— 城池逻辑

**职责**：管理城池的阵营归属、战争状态、颜色渲染和名称标签。

| 成员 | 说明 |
|---|---|
| `owner` | 当前所属阵营（Tech / Design） |
| `AtWar` | 是否处于战争状态 |
| `Setup()` | 初始化城池阵营和显示名称 |
| `SetOwner()` | 切换城池归属，更新颜色 |
| `SetWar()` | 切换战争状态，更新颜色 |
| `ApplyColor()` | 根据状态应用颜色：和平-阵营色 / 战乱-橙色 |
| `CreateLabel()` / `RefreshLabel()` | 创建/刷新城池上方的 3D 文字标签（名称+状态） |

### 5. Billboard.cs —— 公告板组件

**职责**：使挂载该组件的物体始终面向主摄像机，常用于 3D UI 文字。

- `LateUpdate()`：每帧计算并设置朝向，使物体 Z 轴始终对准相机。

---

### 6. FloatingText.cs —— 飘字效果

**职责**：管理伤害/提示文字的生成、上浮、淡出和回收。

| 成员 | 说明 |
|---|---|
| `Pool` / `Active` | 静态对象池与激活列表 |
| `Warm()` | 预创建指定数量的飘字对象 |
| `Spawn()` | 从对象池取出或新建飘字，显示指定内容和颜色 |
| `RecycleAll()` | 回收所有激活的飘字 |
| `Update()` | 控制文字上浮、透明度淡出（生命周期 0.9 秒），生命周期结束后自动回收到对象池 |

---

### 7. DemoFonts.cs —— 字体管理

**职责**：提供统一的中文字体获取接口。

- `Cjk` 属性：按优先级尝试加载系统字体（微软雅黑、黑体、PingFang SC、Noto Sans CJK SC），失败则回退到 Unity 内置 Arial 字体。
- 所有 UI 文字和 3D 文字均通过此接口获取字体，确保中文正常显示。

## 五、技术亮点

1. **对象池模式**：士兵（`ArmyUnit`）和飘字（`FloatingText`）均采用对象池，避免频繁 Instantiate/Destroy，优化性能。
2. **MaterialPropertyBlock**：通过 `MaterialPropertyBlock` 批量修改渲染器颜色，避免运行时产生大量材质实例。
3. **动态 UI 构建**：所有 UI（进攻按钮、战斗 HUD、胜利面板）均在运行时通过代码动态创建，无需预设 UI 预制体。
4. **世界空间 Canvas**：进攻按钮和战斗 HUD 使用世界空间 Canvas + Billboard 组件，使其自然贴合 3D 场景并始终面向玩家。
5. **随机化行军**：士兵出发时间、速度、到达位置均带随机扰动，使行军效果更自然。
